# 03. 화면 및 사용자 흐름

## 1. 승인된 화면 구조

사용자가 승인한 기준은 **기록 / 점검 / 결과 로그**의 세 탭이다. [전체 시안 6장](mockups/README.md)은 기록·점검 화면 v4와 결과 이력 화면 v5를 결합한다. 이미지 승인은 화면 구조에 관한 것이며 실제 구현 완료를 의미하지 않는다.

공통 상단에는 프로젝트, 기기 selectbox, 대상 앱 패키지, proxy 상태/제어를 둔다. 연결한 실제 기기를 PC 화면에서 조작할 수 있다.

## 2. 기록 탭

기록만 담당한다. 점검 항목 checkbox, 선택 항목 요약, 점검 시작 버튼을 넣지 않는다.

- 왼쪽: 연결 기기와 미러링 화면. 미연결이면 연결 안내와 새로고침.
- 가운데: RECORD/STOP, 기록 시간, 동선 목록.
- 오른쪽: 해당 기록 세션의 packet 목록과 요청/응답 상세.
- RECORD는 연결 기기의 입력(터치·키·제스처 등)과 네트워크 packet을 함께 기록한다.
- 미연결이면 RECORD를 비활성화한다. 기록 전에 기기와 대상 앱을 확인한다.
- 화면의 자물쇠/수동 조작 잠금 overlay 및 마스킹 버튼은 제거한다.
- 기록을 끝낸 뒤 점검 탭으로 이동한다.

Proxy ON은 relay 실행 상태이며 기록 세션 생성과 다르다. Proxy OFF 상태에서는 네트워크 수집이 없음을 명시한다. 기록 중 OFF 전환과 진행 중 요청 처리 정책은 상세 명세에서 확정한다.

## 3. 점검 탭: 선택과 실시간 진행

점검 전 선택과 점검 중 진행을 **같은 점검 탭**에서 보여준다. 모호한 '점검 항목 보기' 버튼은 사용하지 않는다.

### 점검 전

- 왼쪽: 기기 화면/정보.
- 가운데: 동선 선택, E/S/U/N 등 분류별 평가항목 checkbox, 선택 개수, 점검 시작.
- 오른쪽: 선택 항목 상세/실행 조건, 시작 전 비어 있는 실행 로그.
- 기기와 선행조건에 맞지 않는 항목은 비활성화하고 이유를 표시한다.
- 기록이 없으면 '기본 앱 실행' 동선을 선택할 수 있다. 거래 동선이 필요한 검사를 충족한 것으로 간주하지 않는다.
- 실행 직전에 선택 기기/앱/항목/동선/packet 조건을 다시 검증한다.

### 점검 중

- 왼쪽: 실제 기기 화면.
- 가운데: 선택한 항목별 대기/실행 중/완료 상태와 나온 판정, 현재 agent, 대기열.
- 오른쪽: main AI와 항목 agent의 실시간 실행 로그, 마지막 heartbeat, 응답/오류 상태.
- 점검 시작 대신 점검 중지와 경과 시간을 보여준다.
- 점검 실행 때문에 결과 로그 탭으로 자동 전환하지 않는다.
- UI의 잠금 표시를 제거해도 **단일 기기 순차 스케줄링은 유지**한다. 동일 기기에 두 검사가 겹치면 안 된다.
- 중지 요청과 실제 도구 종료/정리 완료는 구분한다. 중복 START나 대상 변경이 실행 중 작업의 snapshot을 덮어쓰지 않도록 한다. 세부 입력 처리 방식은 후속 명세로 확정한다.

## 4. 결과 로그 탭: 최종 결과와 이력

실시간 진행 화면이 아니라 **실행이 끝난 점검의 최종 결과**를 조회한다.

- 왼쪽 점검 이력: 날짜·시각으로 실행을 구분하고 검색/선택한다. 패키지와 항목 수를 보조 표시한다.
- 상단 요약: 선택한 실행의 날짜·시각, 기기, 앱, 판정별 건수.
- 가운데: 해당 실행의 평가항목, 양호/취약/판단 불가능, 소요 시간. 항목 검색과 판정 필터.
- 오른쪽: 선택 항목의 판정 사유, 판단 근거, 증적, 후속 조치.
- 이력을 선택하면 요약·항목·증적 모두 동일 run_id의 데이터로 바뀐다. 다른 실행의 증적을 섞지 않는다.
- 현재 연결 기기가 바뀌거나 분리되어도 저장된 과거 실행 결과를 조회할 수 있어야 한다.
- 실행 중 main AI 로그와 대기열은 점검 탭에 남긴다. 결과 탭은 최종 판정 근거와 증적에 집중한다.
- 판단 불가능은 이유가 필수다. 취소·오류·미수행 항목을 양호로 계산하지 않는다.

## 5. 구현 시 주의점

- 시안의 앱/계정/암호/token/금액/주소/증적은 합성 예시다. 마스킹 UI 제거는 실제 비밀값의 Git 업로드나 외부 모델 전송을 승인하는 것이 아니다. 보관·전송 정책은 데이터 계약에서 별도로 정한다.
- Appium이 임의 미러링 입력을 자동 기록한다고 가정하지 않는다. 입력 수집과 재생은 독립 PoC에서 검증한다.
- 그림의 오탈자, 중복 proxy 표시, 증적 날짜 불일치는 구현 명세가 아니다.
- 최종 폰트·색상·간격, 기록 중 proxy 전환, 실행 중 대상 변경 처리, 이력 보존 기간은 아직 상세 확정 대상이다.

## 6. 화면 인수 기준

1. 기록 탭에는 점검 선택/시작 UI가 없다.
2. 점검 전 항목 선택과 실행 중 진행이 점검 탭 안에서 전환된다.
3. 연결/기기/동선/packet 조건을 충족하지 못한 항목의 비활성 사유가 보인다.
4. 실행 상태와 보안 판정을 혼동하지 않는다.
5. 날짜·시각별 이력 선택 시 결과/증적이 해당 실행으로 함께 바뀐다.
6. 최종 결과 탭에서 실시간 실행 중 화면을 표시하지 않는다.
7. 잠금/마스킹 UI를 제거해도 중복 기기 작업 방지와 결과 무결성은 유지한다.
8. 반복 클릭·중단·기기 연결 해제 후 UI와 실제 상태가 일치한다.
