# 03. 화면 및 사용자 흐름 초안

이 문서는 확정 기능을 화면으로 정리한 **와이어프레임 제안**이다. 시각 디자인과 패널 크기, 화면 수는 아직 확정하지 않았다.

## 1. 작업 화면

```text
[프로젝트 / 대상 앱]                    [모델 백엔드 / 상태]
[기기 선택 ▼] [새로고침] [연결·OS·루팅 상태] [Proxy ON/OFF]

[패키지명 또는 APK/IPA 선택] [동선 선택 / 기본 실행]
┌──────────────────┬──────────────────────────┐
│ 기기 미러링 화면 │ 동선 타임라인 / 단계 상세  │
│ 마우스 입력      │ 패킷 목록 / 요청·응답 상세 │
└──────────────────┴──────────────────────────┘
[RECORD] [STOP RECORD] [기록 상태 / 수집 건수]

[검사 항목 체크리스트 / 비활성 사유]
[START] [CANCEL] [현재 항목 / 대기 항목 / 실행 상태]

[판정 요약] [항목별 결과 / 증적 / AI 도구 실행 로그]
```

## 2. 기기 선택과 항목 활성화

- selectbox에 device ID, 모델, OS, 연결 상태를 구분하여 표시한다.
- 기기 변경 시 가능한 항목을 다시 계산한다.
- 루팅/순정 조건을 충족하지 못한 항목은 비활성화하고 원인을 표시한다.
- APK 필요, 기록 필요, 패킷 필요, 도구 부족 등의 선행조건도 함께 표시하는 방향을 제안한다.
- 실행 중 기기 변경은 다른 작업에 영향을 주므로 중단·정리 후 변경하는 흐름을 제안한다.

## 3. RECORD

기록 시작 전에 기기 연결과 조작 경로를 확인한다. 시작 후 입력 이벤트와 proxy 이벤트가 동일 recording ID를 사용하도록 한다.

동선은 목록과 흐름 차트로 확인한다. 각 단계의 동작, 대상, 대기 조건, 시각을 표시한다. 패킷은 방향, 대상, 시각, 크기, 분석 가능 protocol 등을 표시하고 상세를 조회한다.

PC 화면에서 입력했을 때 재현 가능한 동작으로 기록되는지를 먼저 PoC로 검증한다. Appium을 사용한다는 사실만으로 임의 미러링 화면의 모든 조작이 자동 기록되는 것으로 간주하지 않는다.

Proxy OFF 상태의 RECORD는 네트워크 수집 없음으로 명시한다. OFF 전환 중의 연결 처리와 기록 중 전환 허용 여부는 미확정이다.

## 4. START와 결과

START 전에는 선택 기기, 대상 앱, 선택 항목, 동선 유무, packet 범위와 실행 백엔드를 보여준다.

기록이 없으면 '기본 동선: 패키지 실행'을 표시한다. 거래가 필요한 항목에 거래 동선이 없을 때 이유를 노출한다.

진행 화면은 현재 평가항목, 실행 상태, 마지막 진행 이벤트, 현재 도구, 경과 시간과 중단 상태를 구분한다. AI의 숨겨진 사고과정 대신 확인한 사실·도구·증적·판단 근거를 보여준다.

결과에서:
- 양호/취약/판단 불가능을 필터링한다.
- 판단 불가능 사유를 바로 볼 수 있다.
- 판정 근거에서 action/packet/screenshot/tool call로 이동한다.
- 미선택·비활성·취소된 항목을 양호 통계에 포함하지 않는다.

## 5. 화면 인수 기준 제안

- 선택 기기와 맞지 않는 항목을 체크할 수 없다.
- 비활성 사유가 명확하다.
- RECORD와 SCAN 상태를 혼동하지 않는다.
- 기기 단절 시 실제 상태와 UI가 일치한다.
- 취소 요청과 실제 종료 완료를 구분한다.
- 재시도나 반복 클릭으로 동일 기기 검사가 중복 시작되지 않는다.
