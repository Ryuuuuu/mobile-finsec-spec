# Completed synthetic report restart contract

This bounded POC archives only a completed fixed-fixture report. It never resumes replay, restores approval, starts a reviewer, or reads evidence files. A new child explicitly requests a run ID and plan hash; no implicit latest-run fallback is allowed. The archive binds both identities, coverage, sanitized final rows and the approved matching report. UNMATCHED and AMBIGUOUS remain independent of missing acquisition. Existing results without timing detail are reported as HISTORICAL_TIMING_UNAVAILABLE, never reconstructed from the current preview.

The scope is the existing route-A / mock-check, before-check, after-check synthetic fixture. Input and output sizes and counts are bounded; malformed, truncated, incomplete, conflicting identities, checksums or metadata are rejected. A digest detects accidental corruption, not malicious local rewriting or authenticity. Atomic publication uses a temporary file in the same private directory; no active state or raw evidence is archived. Archive failure is separate from replay completion. Existing in-memory v1 behavior remains available.

Small-window reachability is a separate UI check; it must not change this storage contract. Follow-up Android testing, if separately authorized, is restricted to the dedicated cooperative state-only QA fixture and fixed state identifiers; this batch performs no device operation or capture.

## Implemented bounded interface and verification

`load_completed` accepts exactly the caller's `run_id` and `plan_hash` in the existing local stdio API. It returns final report data and `historical_detail`; it does not set the API's owner, task, approval, current preview or active state. The GPUI history picker/restart navigation is not implemented by this batch: child restart and data delivery are verified, not an interactive restarted-window history workflow.

Completed fixture runs publish `completed-reports/<run-id>.json`, limited to 128 KiB, a fixed 2-occurrence matrix, 2 or 4 final rows and at most 4 timing rows. They include only fixed fixture identifiers, bounded enums and evidence references, never the referenced evidence contents. Final coverage is checked against sealed rows; IDs, versions, hashes, required fields and timing binding are checked. Existing `run-id/result.json` is read only when an archive is absent, with HISTORICAL_TIMING_UNAVAILABLE; a malformed present archive is never silently replaced by legacy data. This is compatibility with the known fixture schema, not a general historical report importer.

Publication errors produce `REPORT_ARCHIVE_FAILED` independently of the completed replay result. Only completed replay is archived: failed/cancelled executions remain in their original engine output and are not restartable through this POC. Existing result lookup remains in-memory. There is no latest selection, directory scanning, concurrent-writer guarantee, cryptographic authenticity, power-loss guarantee or production migration claim. A local party able to rewrite both payload and digest is outside the corruption check's guarantee.

Existing observation stdio 3 tests passed with automatic archive/restarted API assertions. All data and files were disposable synthetic fixtures in private temporary directories; no artifact is published.

Future dedicated QA-fixture checks require a separately authorized device run and should compare only fixed state identifiers and their step/occurrence association; they must not be described as real-app matching, vulnerability assessment, enforcement proof or live-state recovery. No such check ran here.
